## Step 3: New scope (after I confirm)
Tramessage is Android-only, uses NFC, and works fully offline.
- Sender: user types a message or https link, taps "Share", and the message is exposed for 30 seconds only (visible countdown, cancel button, wiped after one read or timeout). Optional biometric/device-credential check before arming (on by default).
- Transfer: a Kotlin HostApduService (HCE) with a custom AID emulates an NFC Forum Type 4 tag holding one NDEF record with MIME type `application/vnd.tramessage.msg`.
- Receiver: an intent filter on `android.nfc.action.NDEF_DISCOVERED` for that MIME type auto-launches the app and passes the payload to Flutter via MethodChannel/EventChannel. Handle cold start and warm start.
- NFC gate: on launch check NFC hardware, NFC enabled, and HCE support. If any is missing, show a blocking screen with a button to open NFC settings. The app is unusable without NFC.
- Payload (versioned JSON, max 1 KB): { v, type, content, createdAt, expiresAt, nonce, senderKeyId, signature }.
- Signing: each install generates an Ed25519 or ECDSA P-256 keypair in Android Keystore (StrongBox if available). The sender signs, the receiver verifies. Reject expired payloads (>60 s), reused nonces (small persisted cache), oversized or malformed payloads, and unknown versions. Use audited libraries only, never custom crypto.
- Links: https only, reject javascript:, intent:, file:, data:, strip control characters, never auto-open, show the full URL with an explicit "Open" confirmation. Render text as plain text only.
- Local data: received and sent history stored locally, encrypted with a Keystore-protected key. Provide "clear all data" and an auto-delete timer. No accounts, no login.
- Optional: a screen showing the user's key fingerprint so two people can compare it.

## Step 4: Offline security requirements
